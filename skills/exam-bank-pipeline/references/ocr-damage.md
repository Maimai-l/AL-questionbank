# OCR 损伤类型与处理方法

本文档记录 PaddleOCR-VL 在这批卷子上出现的全部损伤类型及其处理方法。校验
报告出现异常时应先在此对照定位,不要直接修改代码或重跑 OCR。

判断顺序是:先查看 markdown 中的实际内容(用 `sed -n` 查看相关页面),再
决定采取修改规则、补充文本还是重新识别。多数情形前两者即可解决,重新识别
是最后手段。

## 一、JSONL 单行包含多页

结果 JSONL 并非一行一页。单行的 `result.layoutParsingResults` 可能包含
多个页面。按行等同于页解析会静默丢失大部分内容——曾有一本教材因此丢失
75%,直到页数校验不通过才被发现。

处理方法:跨行展平全部 `layoutParsingResults`,页序按出现顺序排列;收尾
断言 OCR 页数等于 PDF 页数。`pipeline/ocr/ocr_books.py` 已按此实现,不要
改回。

## 二、图片引用为 HTML 而非 markdown

Paddle 输出的是 `<img src="imgs/xxx.jpg">`,而非 `![](...)`。编写解析器时
两种形式都要识别。这一点曾导致首次图片校验报告"引用 0 张图",几乎得出
"卷面没有插图"的错误结论。

## 三、两位题号丢失前导位

第 11 题被读作 `1`,第 13 题被读作 `3`。

处理方法:不以题号作为切分锚点,改用选项连排;题号仅作为交叉证据,在
`align_numbers()` 中按"完全相同 +3、个位相同 +2、矛盾 −3"评分。

## 四、选项字母缺失

分三种情形,均由 `repair_option_gaps()` 处理:

```
中间缺失         开头缺失            结尾缺失
A ...            (A 缺失)            A ...
(B 缺失)正文     B ...               B ...
C ...            C ...               (C 缺失)正文  ← 其后为新题号或页尾
```

处理方法:仅在周围结构恰好符合模式时补全。中间缺失要求两侧字母正好相差 2
且中间恰有一行散文;开头缺失要求该行之前是以问号结尾的问句;结尾缺失要求
其后为新题号或页尾。宁可漏补也不能误补。

## 五、整组选项被完全吞没

某题的选项在 markdown 中完全消失,而题干完整。

处理方法:先渲染该页查看。若卷面上确实印有选项,说明是 OCR 遗漏,可尝试
一次 200dpi 重读;重读仍无结果,则将选项文字补入 markdown,并添加
`<!-- 选项自页面图像转录 -->` 注明来源。本次 55 份卷子中约有 30 处只能
如此处理。

## 六、选项被打包进数学块

```
$$ \textbf{A}\quad 30° \textbf{B}\quad 60° ... $$
```

整组选项被压缩为一个 display math 块。

处理方法:`mathblock_options()` 从 `\textbf{X}`、`\mathbf{X}` 或 `\bf{X}`
中抽取升序字母;校验时同样接受这一形态,即答案字母出现在 `\textbf{}` 内
即视为有效。

## 七、图形选项只剩图形而无字母

选项为五张图,字母以 `<div style="text-align:center;">A</div>` 单独成行,
且经常只保留其中两三个。

处理方法:`DIVLET` 将此类 div 归一化为 `A (图形选项)` 文本行;连排检测
允许图形选项之间存在缺口,因为印刷字母必然连续,缺口必为 OCR 丢失;最后
用答案键中的字母补齐范围,例如答案为 E 即说明选项至少延伸到 E。

## 八、页面已有原生字母时重复补充

补充文本时最易犯的错误:页面中其实已存在 `<div>A</div>` 一类原生字母,补充
时又在其下添加一份 `A (见图 A)`,形成两个连排,导致多切出一题。

处理方法:补充前先执行
`grep '<div style="text-align: center;">[A-H]</div>'` 确认是否存在原生字母。
存在则不应补充,或将原生字母中性化为 `(图 A)`。TSA 2023 与 BMAT 2003 均
因此出错。

## 九、UCLES 早期卷子文本层整体偏移 29 位

TSA 2012、2013、2014 一类早期卷子,其嵌入字体将编码整体平移了 29 位:文本
层中的 `:KHQ` 实为 `When`,`\x14` 实为 `1`。人工打开 PDF 阅读完全正常,只有
程序读取文本层时才出现乱码。

处理方法:对每个字符执行 `chr(ord(c) + 29)`。`render_adm_imgs.py` 中的
`unshift()` 即为此用途。不做还原时,这三份卷子一个印刷题号都无法定位,
148 张配图会退化为整页。

这也是此前 32 个 PDF"文本层乱码"的真正原因。OCR 不受影响,因为它读取的是
渲染后的像素。

## 十、题干情境段落被并入上一题

选项折行合并规则过宽时,下一题开头的整段论证会被并入上一题末尾。CT 题失去
论证段完全无法作答,而单独查看两题均显得正常。

处理方法:将折行判据收紧为"上一个选项行不以句末标点结尾,且下一行不以
大写字母、数字或引号开头"。自查方法是统计有多少题的正文以问句开头,即题干
只剩一句 "Which one of the following…"。正常情况下应仅有共享材料题若干道。

## 高 DPI 重读的适用条件与操作

仅在"卷面确实印有内容而 OCR 未能读出"时才值得尝试,且结果不一定更好。

```bash
python3 pipeline/admissions_rebuild/reocr_pages.py                # 自动筛选问题页
python3 pipeline/admissions_rebuild/reocr_pages.py pages.json     # 或指定 {"TSA-2010": [9,16]}
```

操作要点:

- 200dpi 渲染后必须做 JPEG 压缩,quality 取 85。未压缩的 pixmap 单页约 9MB,
  上传会阻塞。
- 原文件自动保存为 `.md.bak`,新版本写在原位置。
- 回收后应逐页比较新旧版本,保留选项连排更完整的一版。本次重读的 192 页中
  有 19 页是旧版更优。
- 服务端上传较慢时(单份耗时 2 至 5 分钟),应先提交全部任务再统一回收,
  不要提交一份回收一份。中断后用 `reocr_recover.py` 从日志中取回任务 ID
  继续。

## 自查清单

修改规则并重跑后,除逐卷报告外,还应执行以下反向检查:

```python
# 1. 是否存在以插图开头的题目——可能是上一题的选项图被误分配
re.match(r"^\s*(<div[^>]*>\s*)?<img", q["text"])

# 2. 是否存在正文以问句开头的题目——情境段落被并入上一题
re.match(r"^(Which|What|How many|How much|How long)\b", stripped)

# 3. 是否存在声明"见图"却不含任何 ![]( ) 的题目——配图被切给了其他题
PICOPT.search(text) and "![](" not in text

# 4. 是否存在空白图片——裁切定位失败
ink = 含暗像素的行数;ink < 3 即视为空白
```

第 3 条已写入 `split_admissions.py` 作为硬校验,其余三条作为排查手段使用。
