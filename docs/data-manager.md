# 题库数据管理页面:需求说明

状态:草稿,待确认。确认前不开始实现。

## 1. 背景

### 1.1 题库现状

| 项目 | 数量 |
|---|---|
| 考试 | 9709、9231、9618(CAIE A Level),TMUA、TSA、BMAT(入学考试) |
| 题目 | 5937 道,每道一条记录,ID 形如 `9709_s23_12_q05`、`TMUA-2023-P1-q1` |
| 题图 | 每题一张紧凑题图;2885 道 CAIE 题另有带答题区的题图 |
| 评分细则 | 5936 道有,按小问切开 |
| 详解 | 874 道(9618 卷 1–3) |
| 原卷与细则 PDF | 本机 `raw/pdf/`(380 MB)、`raw/ms/`(308 MB),不在 `data` 分支里 |

### 1.2 使用方式

以下是我对你的使用方式的理解,第 8 节列出需要你确认的地方。

1. **刷整卷**:打印原卷,在纸上作答。
2. **刷专题**:按主题跨试卷选题。为了省纸,把选好的题拼成一份文档,放进 white-board 应用,在 iPad 上作答。
3. **判分与讲解**:交给模型(Claude)。
4. **交给模型的方式**:题目、评分细则和你的作答,要尽量一次交齐,减少来回。现有的导出脚本和截图工具都是为此服务的:导出脚本整理出模型需要的题目信息,截图工具把 iPad 上的作答快速取出来。白板已经能替代截图工具。
5. **数据维护**:由 Claude 用 pipeline 完成,你不在页面上改数据。

### 1.3 结论

需要的不是作答界面,而是一个**只读的数据管理页面**,做三件事:

- 查得到:题库里每道题的每项数据都能查询和查看。
- 选得出:把需要的题组成题组。
- 导得出:按下游的要求生成文件,包括打印用 PDF、白板文档,以及交给模型的资料包。

## 2. 目标与范围

### 2.1 目标

| 编号 | 目标 |
|---|---|
| G1 | 在一个页面里查询全部题目,查看每道题的全部数据 |
| G2 | 把选中的题组成题组;题组是所有产出的唯一输入 |
| G3 | 由题组生成打印 PDF、白板文档、模型资料包 |
| G4 | 交给模型的资料一次交齐:资料包自带清单与说明,模型不需要再追问 |
| G5 | 现有的各个导出脚本归入同一套"题组 + 输出格式"的做法,不再各写一份 |

### 2.2 不做的事

- 不在页面上修改题库。页面对 `data/caie.db` 只读,数据问题由 Claude 处理。
- 不做网页作答。现有的练习页(`app/`)暂停使用,代码保留,其中的服务端、题图服务和分码解析可以复用。
- 不做截图回传。白板已经替代截图工具。
- 不做页面内判分。判分交给模型。

## 3. 使用流程

### 3.1 刷整卷

1. 查询并找到一份试卷,例如 `9709/12/M/J/23`。
2. 打印原卷 PDF。这是原卷页面,带原卷答题区。
3. 在纸上作答,拍照或扫描。
4. 生成这份试卷的模型资料包(题目、评分细则),连同作答照片一起交给模型判分。

### 3.2 刷专题(白板)

1. 按条件查询,例如"9709 卷 3,主题 3.8 微分方程,2021 年以后"。
2. 从结果中勾选题目,组成题组并命名。
3. 生成白板文档:每题用带答题区的题图,按题组顺序拼成一份 PDF,自动在 white-board 里新建文档板,放在统一的文件夹中。
4. 在 iPad 上的 white-board 里作答。
5. 回到页面,从白板导出带笔迹的 PDF,和题组的评分细则一起打包成模型资料包,交给模型判分。

### 3.3 由模型出题组

1. 让模型按需求选题。模型返回题组 JSON,格式沿用你截图工具里的 `alevel-question-set/v1`。
2. 页面导入这份 JSON,成为一个题组。
3. 后续同 3.1 或 3.2。

### 3.4 问几道题

1. 选几道题组成临时题组。
2. 复制或下载资料包(题干文本、题图、评分细则),交给模型。

## 4. 核心对象

| 对象 | 内容 | 存放 |
|---|---|---|
| 题目 | 题库中的一条记录:ID、考试、卷别、考季、题号、分值、小问、主题、题型、题干文本与 LaTeX、题图、评分细则、详解、质量评级 | `data/caie.db`,只读 |
| 查询 | 一组筛选条件,可以命名保存,例如"9709 P3 积分 2021+" | `paths.WORK` |
| 题组 | 名称、来源(查询 / 模型 / 手选)、有序的题目 ID 列表、创建时间、备注;可导出为 `alevel-question-set/v1` | `paths.WORK` |
| 产出 | 由题组生成的文件:打印 PDF、白板文档、资料包;记录题组、选项与生成时间 | `paths.WORK` 下的产出目录 |

题组和产出是你的个人数据,不进 `data/`,也不随 `sync.py` 推送。

## 5. 功能需求

每一项后面附验收标准。

### F1 查询

- 表格,每行一道题。列可以选择显示或隐藏,包括试卷代码、题号、小问数、分值、主题、子主题、题型、有无图形、有无详解、质量评级。
- 筛选条件:考试、卷别、变体、年份范围、考季、主题(可多选)、分值范围、题型、有无详解、质量评级。条件之间是"并且"的关系。
- 全文搜索题干,按试卷代码跳转(例如输入 `s23 12 q5`)。
- 点列头排序。
- 结果条数、分值合计随条件实时更新。

验收:对全部 5937 道题,筛选和排序在 0.1 秒内完成;同一组条件得到的结果与在 `caie.db` 上执行等价 SQL 的结果一致。

### F2 单题详情

- 显示一道题的全部字段:紧凑题图与带答题区题图(可切换)、题干文本与 LaTeX(可复制)、按小问的评分细则、详解、主题与置信度、质量评级、来源 PDF 与页码。
- 在详情中直接加入或移出当前题组。

验收:任意一道题的每个非空字段都能在详情中看到。

### F3 题组

- 创建方式有三种:
  - 从查询结果勾选;
  - 把整个查询结果加入;
  - 导入模型返回的题组 JSON。导入时列出题库中找不到的 ID。
- 在题组内调整顺序、移除题目、改名、写备注。
- 题组列表:名称、题数、总分、来源、创建时间、已生成的产出。
- 导出题组 JSON(`alevel-question-set/v1`)。

验收:导入一份 JSON 再导出,题目 ID 和顺序不变;刷新页面后题组仍在。

### F4 打印 PDF

单题拼版:

- CIE 题目用带答题区的题图,沿用原卷的答题区,不重新排版;没有带答题区题图的题用紧凑题图。
- 入学考选择题用紧凑题图,可以多题共一页。
- 每道 CIE 题从新的一页开始。题图在原卷换页处换页,不在原卷一页的中间断开。
- 页脚印题组名、试卷代码、题号、页码。
- 选项:在末尾附评分细则,或单独生成一份细则 PDF。

整卷:

- 直接输出原卷 PDF,可附评分细则 PDF。依赖第 8 节问题 Q1。

验收:打印出来的每页与原卷同等清晰(题图 150 dpi,按 A4 宽度排版);每道题的答题区与原卷一致。

### F5 白板文档

- 用与 F4 相同的版式生成 PDF,通过 white-board 的文档板接口新建文档板(`POST /api/doc?folder=…`),放在统一的文件夹里。文档板名就是题组名。
- white-board 把 PDF 原件复制到它自己的 `docs/`,笔迹存为矢量。导出时笔迹合进原 PDF(`/api/export/<白板 id>`),体积只增加笔迹本身。
- 管理:页面列出每个题组对应的白板,包括是否已建、最后修改时间、有无笔迹;可以导出带笔迹的 PDF,并把它加入资料包。

验收:由一个题组生成的白板,在 iPad 上打开时页面顺序与题组一致;导出的 PDF 含全部笔迹。

依赖:white-board 在本机运行。新建文档板需要"管理白板"权限,Mac 本机默认具备。

### F6 模型资料包

- 一个 ZIP,内容如下:
  - `manifest.json`:题组名、每道题的 ID、试卷代码、分值、小问、主题、文件索引;
  - 每题的题图;
  - 题干文本与 LaTeX;
  - 按小问的评分细则;
  - 详解(如有);
  - 可选:作答文件,即白板导出的 PDF 或照片。
- 两种体量:完整版(全部字段与题图);精简版(只有文本,题图只保留文本无法表达的部分,例如图形)。
- 附一份给模型的说明,写明这包资料里有什么、文件怎样对应、希望模型做什么(判分、讲解、出题),使一次提交就够用。
- 现有导出脚本(`pipeline/export/export_*.py`)改为"一个保存的查询 + 一种输出格式",统一从这里生成。

验收:模型只拿到资料包,就能按题号和小问逐项判分,不需要追问题目内容或评分细则。

### F7 数据状况(只读)

- 每门考试列出需要处理的记录:题图缺失、带答题区题图缺失、评分细则缺小问、总分与各小问之和不一致、识别质量为 partial、主题置信度低。
- 每一项都是一个可以打开的查询;可以复制题目 ID 列表,交给 Claude 处理。

验收:这里的数字与 pipeline 审计脚本(`audit_text.py`、`audit_crops.py`)的结果一致。

## 6. 非功能需求

| 项目 | 要求 |
|---|---|
| 运行 | Mac 本机服务(`python3 qb.py serve`),局域网内的 iPad 也能访问;不依赖外网 |
| 数据 | 对 `data/` 只读;题组、查询、产出存 `paths.WORK`;所有路径经 `lib/paths.py` |
| 性能 | 全库筛选与排序 0.1 秒内完成;50 道题的 PDF 在 10 秒内生成 |
| 稳定性 | 题目 ID 不变;题库更新(`sync.py pull`)后,题组照常可用;题组里已不存在的 ID 会被单独列出 |
| 设计 | 见第 7 节 |

## 7. 设计语言

沿用你截图工具页面(`question_set_viewer.html`)的做法:

- 白、墨、灰,不用第二种颜色;直角,细线,留白。
- 层级只靠字重和灰度区分,不靠颜色。
- 信息分三层:
  - 一直可见:表格、当前题、主要动作;
  - 需要时可见:详情、题组内容;
  - 异常时才出现:错误与缺失。
- 不加说明性文字。动作用最短的名称或图标(见 Q6)。
