5.1.1为什么需要操作系统

操作系统站在用户、应用程序和硬件中间:给程序提供运行的环境,给用户提供操作的界面,并把硬件的复杂细节藏起来。

操作系统operating system是给应用程序提供运行环境、并在硬件与用户之间提供接口的软件(software that provides an environment in which applications can run and an interface between the hardware and the human user)。评分细则接受的作用有三条:隐藏硬件的复杂细节(hides the complexities of the hardware from the user)、提供软件运行的平台(provides a platform for software to run)、提供用户界面user interface(provides a user interface)。

了解图形界面和命令行
界面怎么用特点
图形界面点图标、窗口、菜单(GUI: icons, windows, menu, pointing device)不用记命令,容易上手
命令行键入命令(CLI: command line interface)命令必须一字不错;用户直接与计算机沟通,不受预设选项限制
了解开机时操作系统怎样进内存

操作系统存放在硬盘上,开机由 BIOS 负责启动;只把需要的部分复制进 RAM,因为操作系统太大,全部载入会拖慢计算机(the required part of the operating system is copied into RAM)。

5.1.2五项管理任务

操作系统的任务分成五项管理:内存、进程、硬件、文件、安全;考试要么让你说出名称,要么让你连线配对作用。

真题有两种问法:直接问是哪几项管理任务(identify four key management tasks that the operating system will perform),或者把任务和作用连线。评分细则里还接受:提供软件运行的平台(provision of a platform for software)、提供用户界面、错误检查和恢复(error checking and recovery)。下面几节逐项展开。

必考配对:管理任务 → 作用

管理任务作用
内存管理把内存动态分配给进程(dynamically allocates memory to processes)
进程管理让进程之间传递数据(allows processes to transfer data to and from each other)
硬件管理为接在外部端口的设备安装驱动程序(installs programs for devices connected to external ports)
文件管理标出未分配的文件存储空间,供使用(marks unallocated file storage for availability)
安全管理验证用户和进程的身份(validates user and process authenticity)

5.1.2内存管理与进程管理

内存管理让每个程序各占一块内存、互不覆盖;进程管理决定下一个轮到谁用处理器;两者合起来,计算机才能同时运行多个程序。

内存管理memory management控制主存,把内存分配给进程,并阻止数据互相覆盖(stops the data from overwriting each other in RAM);它决定哪些进程放在主存里(decides which processes should be in main memory),动态分配并收回不用的内存(dynamic allocation of RAM to programs / processes; reclaims unused blocks of RAM)。进程管理process management决定下一个运行哪个进程(decides which process is to be run next),并在进程之间切换,让它们共用处理器(switches between processes to allow them to share the use of the processor)。有了这两项,多任务multitasking才能实现:计算机同时执行,或者看起来同时执行多个进程(carry out / seem to carry out more than one process at a time)。

常考解释内存管理和进程管理怎样支持多任务

任务怎样支持多任务
内存管理把所有正在运行的程序的数据同时放在 RAM 里(stores data from all currently running programs concurrently in RAM);阻止数据互相覆盖(stops the data from overwriting each other)
进程管理让一个进程暂停,同时处理另一个进程(allows one process to be paused whilst another process can be actioned);决定下一个运行谁,并在进程之间切换
了解内存管理的三个部分:优化、组织、保护
部分做什么
内存优化记录哪些内存已分配、哪些空闲,决定怎么分配和收回(memory optimisation: how memory is allocated and deallocated);需要时在内存和硬盘或 SSD 之间换入换出数据
内存组织决定给每个程序多少内存、怎么划分(memory organisation):单一连续分配、分区、分页(每页大小固定,用于虚拟内存)、分段(按逻辑分组,不要求连续)
内存保护保证两个程序不能同时使用同一个内存位置(memory protection),否则数据会丢失、结果会出错,甚至死机

5.1.2硬件管理与设备驱动

硬件管理负责所有输入输出设备:靠设备驱动程序和设备沟通,用队列和缓冲区把要发送的数据排好。

硬件管理hardware management控制输入输出设备,靠设备驱动程序、缓冲区和队列工作(controls input and output devices using device drivers, buffers and queues)。设备驱动程序device driver让操作系统能和硬件通信,把数据翻译成设备能懂的格式(translates data into a format the device understands);接上新设备时,由硬件管理装入并安装驱动(installs driver software for devices connected to external ports)。硬件管理还给每个设备设定优先级,并处理设备发来的错误信息和中断(manages hardware interrupts)。

了解队列和缓冲区有什么不同

缓冲区临时存放数据,等设备准备好了再传给它(a buffer temporarily holds data until it is ready to be transmitted to the device)。打印机正忙,或者这个打印任务优先级低时,数据先进打印队列,轮到它时再进缓冲区。

5.1.2文件管理与安全管理

文件管理组织文件和目录、控制谁能使用;安全管理保护数据,办法是账户、密码和访问权限。

文件管理file management组织文件、维护目录结构,控制文件的访问权限,并执行新建、打开、删除、复制等操作(organises files; maintains directory structures; access rights; create, open, delete, copy)。安全管理security management保护数据的完整性、保密性和可用性(integrity, confidentiality and availability of data),评分细则接受的做法有:管理用户账户(managing user accounts)、验证用户和进程(authentication // validating users and processes)、设置访问权限(implements access rights and permissions)、提供丢失数据的恢复(recovery of lost data)、及时做系统安全更新(operating system security updates)、记录日志(auditing and keeps logs of activity)。

了解文件系统由格式化决定

文件怎样在磁盘上存放,由格式化时选的文件系统决定,例如 Windows 用 NTFS(the logical file storage format, such as FAT or NTFS);打开文件时,文件管理把文件从硬盘或 SSD 读入内存。

5.1.3实用程序

实用程序是维护计算机的小工具:格式化、杀毒、整理、修复、备份、压缩;考试常考「工具名 → 用途」配对。

实用程序utility software是系统软件,做维护和日常整理的工作(perform housekeeping/maintenance tasks // improve overall performance)。磁盘格式化程序disk formatter初始化磁盘(prepares a disk for future use),建分区、设文件系统、建引导扇区,并清除所有数据(creating partitions; setting the file system; creating a boot sector; erasing all data)。病毒检查程序virus checker扫描恶意代码。磁盘修复disk repair检查并修复磁盘上的不一致(check for and fix inconsistencies on a disk)。备份软件back-up software复制数据,以防原件丢失或损坏(creates a copy of data in case the original is lost)。

常考举一个实用程序,解释为什么需要它

实用程序为什么需要
碎片整理反复保存、删除小文件,磁盘会碎片化(over time saving and deleting of small files fragments the disk);整理后文件连续,访问更快(access time to the files is improved)
磁盘修复找出并标记坏扇区(identify and mark bad sectors),还原损坏的文件(restore corrupted files)
文件压缩缩小文件,省存储空间,缩短传输时间(saves storage space; reduces transmission time)
磁盘格式化为使用磁盘做准备,分区、设置文件系统(prepare a disk for use; set up the file system; partition the disc)

启发式检查是检查软件有没有可能是病毒的行为,能发现数据库里还没有的新病毒(behaviour that could indicate a possible virus)。用户明知文件没问题却被报为感染,叫误报(false positive)。病毒库要不断更新,还要定期做全盘检查。

了解备份:最好有三份
工作版本internal HDD →本地备份portable SSD →远程备份cloud storage

备份工具可以定时备份,而且只在文件有改动时才备份(a schedule for backing up files; only back up if a file has changed)。

了解格式化与坏扇区

先建分区,再格式化:在每个分区开头写入目录和目录表,操作系统才找得到文件。完全格式化会把原有数据清掉。格式化程序还能检查每个扇区,发现坏扇区就标记,并用新的空扇区替换(bad sectors are flagged and replaced with unused sectors)。

坏扇区成因
硬坏扇区(hard)制造缺陷;读写头碰到盘面;系统崩溃损伤盘面,难修复
软坏扇区(soft)突然断电;静电造成部分扇区数据损坏

5.1.3磁盘碎片整理

文件散落在磁盘各处,磁头要来回移动才读得完;碎片整理把每个文件的块排到一起,磁头少动,访问就快。

碎片整理软件defragmentation software重新排列文件的各个部分,使每个文件连续存放(moves parts of files so that each file is contiguous),并把空闲空间集中在一起(collects all the free space together)。这样读取下一部分文件时,磁头不用移动那么多(the disk head does not need to move as much to access the next part of the file),访问更快。

常考解释为什么要碎片整理

反复保存、删除、扩展文件files are deleted and extended
→
文件的块散落在磁盘各处blocks scattered, not contiguous
→
读一个文件,磁头要移动很多次several head movements
→
整理后连续存放,访问更快contiguous: access time improved
了解碎片整理的限制

磁盘快满时,碎片整理可能做不成。SSD 的读取方式不同,碎片问题小得多(less of a problem with SSDs)。有些整理程序还会把多次读写后损坏的数据块标为不可用,以后不再往里写。

5.1.4程序库与动态链接库

库例程是写好、测好的子程序,直接调用就行;动态链接库在运行时才调入,所以程序更小,多个程序还能共用。

程序库program library是预先写好、预先编译、预先测试过的子程序的集合,可以在别的程序里调用(set of pre-written / pre-compiled / pre-tested routines which can be called in other programs)。库里的每个子程序叫库例程library routine。动态链接库dynamic link library (DLL)把库例程放在单独的文件里,运行时才链接,需要时才载入内存(loaded only once / when required),一个文件可供多个程序同时使用(a single DLL file can be made available to several application programs)。静态库则是在编译时就把库例程嵌进可执行代码(linked to the executable code at the time of compilation)。

必考使用库例程的好处与缺点

好处缺点
少写代码,省开发时间(less code to develop as code is pre-written)可能与当前程序不兼容(compatibility issues)
已测试、有文档,减少测试时间,更可靠(pre-tested and documented)不一定经过充分测试(not guaranteed to be thoroughly tested)
团队共用,程序之间保持连续性(continuity between programs / programmers)不一定完全符合需要,要修改再测试(may not match needs exactly)
源代码更易读,只需调用(the routine is simply called in the source code)别人改了库例程,可能出现意外错误(if later edited by someone else, unexpected errors)

必考使用 DLL 的好处与缺点

好处缺点
占内存少,只在需要时载入一次(main memory requirements reduced as the DLL is loaded only once / when required)运行时所有 DLL 都必须在,否则报错甚至崩溃(all DLL files need to be available at run time)
可执行文件更小(the executable does not contain the library routines)DLL 被改动或损坏,主程序会出现意外结果(changed or corrupted DLL: unexpected results)
DLL 更新后不用重新编译主程序(no need to recompile the main program)DLL 可能被恶意程序改动(malicious changes to DLL files)
一个 DLL 可供多个程序同时用(available to several application programs)主程序里的链接部分也必须在运行时可用(the linking software must be available at run time)
了解库为什么方便团队开发

用库可以做到模块化编程,几个程序员能同时开发同一个软件(modular programming: several programmers working on the same software at the same time);同一系列的软件也能保持一致的风格。

5.2.1三种翻译器

计算机只能执行机器码,其他语言写的程序都要先翻译:汇编器翻译汇编语言,编译器一次翻译整个高级语言程序,解释器一行一行翻译并立刻执行。

汇编器编译器解释器
源程序汇编语言高级语言高级语言
目标程序有有无
每行源码产生1 条机器码多条多条

翻译器translator是把机器码以外的语言写的源程序翻译成机器码的系统软件(the systems software used to translate a source program written in any language other than machine code)。汇编器assembler把汇编语言翻译成机器码(translate assembly code into binary/machine code),一行汇编对应一条机器码。编译器compiler一次翻译整个高级语言程序(translates all the code at the same time),生成可执行文件(produces an executable/.exe/object code file that can be run without the source code)。解释器interpreter一次翻译一行,翻译完就运行(translates one line of a high-level language program at a time, and then runs that line of code)。

了解机器相关与可移植

汇编语言机器相关,换一种芯片就不能用(machine dependent, not portable);高级语言与机器无关,只要有对应的编译器或解释器,在哪种计算机上都能运行(machine independent, portable)。编译后的程序存起来可以反复运行,只有源代码改动了才需要重新翻译。

5.2.2编译还是解释

写程序时用解释器:出错就停,改完接着跑;写完用编译器:生成可执行文件,反复运行,用户看不到源代码。

评分细则的说法:写程序时用解释器,测试、调试尚未完成的程序(use an interpreter while writing the program, to test/debug the partially completed program),因为错误可以马上改,从停下的地方继续(errors can be corrected in real time; processing continues from where the execution stopped)。程序写完后用编译器,生成可执行文件,源代码不会被用户看到(use the compiler after the program is complete, to create an executable file so source code not seen);对已完成的部分反复测试,不用每次重新解释(repeatedly test the same completed section without having to re-interpret every time)。

必考比较编译器与解释器

编译器解释器
怎样翻译一次翻译全部代码(translates all the program at the same time)一次一行,翻完立刻运行(translates one line and then runs it)
出错时有错误程序就不能运行;一个错误可能引出别的假错误(the program will not run if there are any errors; one error may result in other false errors)遇到错误就停下,当场改正(errors can be corrected in real time)
运行速度已翻译好,运行快(shorter time to execute)每次运行都要重新翻译,较慢
测试未完成的程序不行(a compiler cannot translate a partial program)可以,只测其中一段(a partially completed program can be tested on its own)
交给用户的可执行文件,用户不需要编译器(users do not require the translator to run the program)源代码,用户需要解释器
了解部分编译、部分解释(Java、Python)
源代码source code
→
编译器compiler
→
字节码bytecode / intermediate code
→
解释器运行interpreter on a virtual machine

字节码bytecode是编译后得到的、与机器无关的低级中间代码(intermediate code / p-code)。部分编译、部分解释的原因,评分细则有三条:字节码在运行时才被解释,所以能在不同平台上用(can be used on different platforms as they are interpreted when run);运行时生成的机器码针对 CPU 优化(code is optimised for the CPU as machine code is generated at run time);源代码不用重新编译,运行更有效率(source code does not need recompiling)。

5.2.4集成开发环境(编码与呈现)

IDE 把写代码、翻译、调试放在同一个软件里;写的时候有提示、会排版、边写边查语法错误。

集成开发环境IDE (integrated development environment)是用来编写、翻译和测试高级语言程序的一套程序(a suite of programs used to write, translate and test a program),通常有源代码编辑器、编译器或解释器、带调试器的运行环境。编辑器里常见的功能有:上下文提示context-sensitive prompt在用户输入时给出代码建议、自动补全(gives suggestions for code as the user types // automatically complete statements);动态语法检查dynamic syntax checking在输入时就标出不符合语言规则的语句(underlines or highlights statements that do not meet the rules of the language);代码美化排版prettyprinting给关键字着色、自动缩进(colour code keywords so the user can identify any errors; auto indentation / formatting);展开/折叠代码块expand/collapse code blocks让用户收起暂时不用的代码(the user can hide code that they are not currently working on)。

5.2.4集成开发环境(调试)

调试靠三样:断点让程序停在指定的行,单步执行一次只跑一行,报告窗口显示这时变量的值。

断点breakpoint是在选定的某一行让程序有意停下,好检查变量的内容(stop the code running at a set point to check the flow/variable contents)。单步执行single stepping是一次只运行一行,检查变量的值(run the code one line at a time so the values can be checked),能看到每一行代码的效果(shows the effect of each line of code)。报告窗口report window是 IDE 里单独的窗口,显示程序运行时变量和表达式的内容(outputs the contents of variables and data structures)。
